# SPEC-08 — API contract

> **Status:** v1 (2026-11-19) · **Owner of:** the index of every endpoint and the one error shape
> Base path `/api/v1`. JSON is camelCase. Every request except `GET /health` and `GET /api/v1/config` needs the `X-Demo-User` header ([SPEC-09 §3](SPEC-09-security-and-access.md)). `/config` is public because the UI reads the demo user list from it before a user is chosen.
> The OpenAPI document is generated by FastAPI and exported to `backend/openapi.json` for the frontend types.

## 2. Error shape

Every error is `application/problem+json`:

```json
{ "status": 409, "code": "duplicate_document", "title": "Duplicate document",
  "detail": "This file is already uploaded as \"HR Employee Handbook 2026\".",
  "errors": { "file": ["…"] }, "traceId": "4f1c…", "existingId": "…" }
```

`errors` (field → messages) only on 422. Extra members are allowed per code (e.g. `existingId`, which is present only when the caller can see the existing document; otherwise the `detail` names no title). The same shape matches the Private Repo App `ApiProblem` type used by `http.ts`.

| Status | `code` | When |
|---|---|---|
| 400 | `bad_request` | Malformed body |
| 401 | `unknown_user` | Missing or unknown `X-Demo-User` |
| 404 | `not_found` | Unknown id, **or a document the user may not see** (never 403, so existence doesn't leak) |
| 405 | `method_not_allowed` | Known path, wrong HTTP method |
| 409 | `duplicate_document` | Same hash already uploaded (`existingId` and title only if visible to the caller, [SPEC-03 §2](SPEC-03-ingestion.md)) |
| 409 | `ingest_in_progress` | Re-ingest while a job is queued/running |
| 413 | `file_too_large` | Over `MAX_UPLOAD_MB` |
| 415 | `unsupported_type` | Not an allowed type by content |
| 422 | `validation_failed` | Field errors |
| 422 | `query_too_long` | Question/search over 1,000 characters |
| 429 | `rate_limited` | Provider rate-limited after retries |
| 503 | `quota_exhausted` | Provider plan quota or PAYG balance used up |
| 503 | `provider_unavailable`, `provider_auth`, `model_not_allowed` | Provider problems ([SPEC-06 §5](SPEC-06-ai-providers.md)) |
| 500 | `internal` | Anything else, including provider `context_too_long` / `request_too_large` that reach a request (`detail` is generic; details are in logs with `traceId`) |

## 3. System

- `GET /health` → `200 { status: "ok", db: "ok", aiProvider: "ilmu" | "fake" | … }`; `503` with `db: "error"` when the DB is down.
- `GET /api/v1/config` (no `X-Demo-User` needed) → `{ allowedExtensions: [".pdf", …], maxUploadBytes, demoUsers: [{ id, name, groups }], accessGroups: ["all", "hr", …], docTypes: [...], orgName }`. In `cloudflare_access` mode `demoUsers` is empty.
- `GET /api/v1/me` → `{ id, name, groups }`.

## 4. Documents

**Document** JSON: `{ id, title, filename, fileType, contentType, sizeBytes, docType, department, effectiveDate, version, language, status, accessGroups, pageCount, summary, tags, ingestStatus, ingestErrorCode, ingestError, chunkCount, uploadedBy, createdAt, updatedAt }`.

### 4.1 Upload
`POST /api/v1/documents` multipart: `file` (required), `title`, `docType`, `department`, `effectiveDate` (YYYY-MM-DD), `accessGroups` (repeat the field). → `202 Document` (`ingestStatus: "queued"`). Errors: 409 `duplicate_document`, 413, 415, 422. `accessGroups` must be a subset of the user's own groups (you can't upload what you can't see).

### 4.2 List and get
`GET /api/v1/documents?status=current|superseded&ingestStatus=…` → `{ items: Document[] }` sorted by `createdAt` desc. Only documents whose `accessGroups` overlap the user's groups. No paging in the MVP (≤ 500 documents).
`GET /api/v1/documents/{id}` → `Document` or 404.

### 4.3 Patch
`PATCH /api/v1/documents/{id}` JSON, all optional: `title`, `docType`, `department`, `effectiveDate`, `version`, `status`, `accessGroups`. → `200 Document`. Status and groups changes propagate to chunks ([SPEC-03 §1](SPEC-03-ingestion.md)).

### 4.4 Delete
`DELETE /api/v1/documents/{id}` → `204`.

### 4.5 File
`GET /api/v1/documents/{id}/file` → the original bytes, `Content-Type` from the document, `Content-Disposition: inline; filename*=UTF-8''…`, `X-Content-Type-Options: nosniff`. 404 for documents the user can't see.

### 4.6 Re-ingest
`POST /api/v1/documents/{id}/reingest` → `202 Document` (`ingestStatus: "queued"`), or 409 `ingest_in_progress`.

### 4.7 Chunks
`GET /api/v1/documents/{id}/chunks?offset=0&limit=50` or `?around=<chunkId>&radius=2` (`around` must be a chunk of `{id}`, else 404) → `{ items: [{ id, ordinal, chunkType, text, headingPath, section, pageStart, pageEnd, sheet, tokenCount }], total }`.

### 4.8 Replace file
`POST /api/v1/documents/{id}/file` multipart: `file` (required) → `202 Document` (`ingestStatus: "queued"`). Same id, title, metadata and access groups; the filename, type, size and hash come from the new file and the old stored file is removed. The old chunks stay searchable until the new set swaps in (as for re-ingest). Errors: 404, 409 `ingest_in_progress`, 409 `duplicate_document` (same bytes as this or another live document), 413, 415.

## 5. Search

`POST /api/v1/search` `{ query, topK? }` (`topK` 1–20, default `TOP_K`; else 422 `validation_failed`) → `{ hits: [{ chunkId, documentId, title, fileType, headingPath, section, pageStart, pageEnd, sheet, effectiveDate, score, vecRank, ftsRank, vecSim, rerankScore, snippet }] }`.

## 6. Chat

`POST /api/v1/chat` `{ question, history?: [{ question, answer }] (≤ 4) }` → `200 text/event-stream` with the events in [SPEC-05 §6](SPEC-05-answering.md). Each history `question` is ≤ 1,000 characters and each `answer` ≤ 4,000. Validation errors before the stream starts are normal problem responses (422). Provider errors after the stream starts arrive as an `error` event.

FastAPI can't describe SSE payloads, so `app.export_openapi` adds the event models to `components.schemas` as `SseMeta`, `SseSources`, `SseDelta`, `SseDone` and `SseError`. The frontend generates its event types from them.

## 7. Usage

`GET /api/v1/usage/summary?from=&to=` → `{ byModel: [{ model, role, purpose, calls, promptTokens, completionTokens, costMyr }], questions: { count, avgLatencyMs, avgFirstTokenMs, avgTokens }, ingestion: { documents, chunks, embedTokens }, balances: { planTokens, paygMyr, readAt } }`.

## 8. Acceptance checks

1. Every row of §1 exists in the generated OpenAPI document, and no undocumented route exists (test compares route list to this table).
2. Every error response has `status`, `code`, `detail`, `traceId` and the `application/problem+json` content type.
3. A document outside the user's groups returns 404 on get, patch, delete, file, chunks and reingest; `chunks?around=` with a chunk of another document returns 404.
4. Missing `X-Demo-User` returns 401 `unknown_user` on every `/api/v1` route except `GET /config`, which returns 200.
5. JSON responses are camelCase.
6. The generated OpenAPI document contains the five SSE event schemas.
